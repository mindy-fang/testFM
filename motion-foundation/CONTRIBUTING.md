# 子项目开发约定

本说明中的相对路径和命令以 `motion-foundation/` 为起点。Git 在上层 `testFM` 仓库统一管理，修改范围限于本子项目及其专用自动检查配置。

## 新增数据集

1. 在`src/motion_foundation/datasets/`增加解析模块，不将格式分支写进模型。
2. 使用`motion_foundation.corpus.Builder`输出`v13-native-corpus-1`清单；参考`examples/add_dataset.py`。公共写入器负责连续段、观测掩码、缓存哈希和相对路径。
3. 明确单位、时间来源、主体命名空间、来源哈希及原始采集分组。默认划分哈希不保证小数据集同时有train/validation/test，正式池需审核并冻结。
4. 未知单位不能猜；零填充必须在`observed=False`后；时间倒退拆段而非排序；超过0.5秒缺口不跨窗；同受试者/原始采集及派生内容不可跨划分。
5. 同步证据不足按独立器件流；已知重采样依赖前不启用时间掩码重建。编码兼容、目标可用、可靠融合分别判断。
6. `configs/datasets.json`增加来源状态与限制；不将真实波形或身份映射提交Git。
7. 加入合成原始格式测试，完成`motion-validate --manifest ...`真实数据验证后再申请准入正式池。自动检查只跑合成测试。

Builder的`groups`定义为`cols`、`channels`和`modality`，每个IMU组只含一个器件，不重复同物理量/轴；压力组不假定16个点。不把缓存路径、数据集来源或受试者标识作为模型输入特征。修改Writer前补充缓存碰撞和划分测试。

## 修改模型

- 首选配置调整`configs/v13.json`；入口为`registry.build_model()`。
- 模型变体注册到`MODELS`，参考`examples/model_variant.py`；新进程必须导入注册模块，不能只写一个未加载的注册文件。
- 标准编码入口为`encode(Sample, visible=None) -> RepresentationBundle`，明确支持的局部、器件与共享时间特征。
- 对V13兼容变体，保持`config_dict()`、配置类型与标量语义接口，才能复用现有目标。新架构必须配套修改目标和保存加载规则，不把注册成功当兼容证明。
- 通用压力主干不增加跨布局测点ID/几何身份；不以固定通道数、双脚或采样率作为隐式前提。
- 行为保持重构应对同权重/同输入比较输出及loss；算法变更注明参数键和检查点兼容性。

## 修改目标与训练

去噪与掩码目标当前协议不同；不要假定`TrainingEngine`能直接驱动去噪，也不要让掩码加载器读取去噪检查点。新增目标需注明准入条件、合法监督支持、损失归约和无目标跳过规则，并测试隐藏值隔离与主干梯度。

仅自检不更新参数。训练需显式授权及执行标志；GPU任务手动选择空闲卡。正式test不可用于调参或模型选择。

## 提交检查

```bash
python -m ruff check .
python -m pytest -q
motion-selfcheck
```

PR应分清数据适配、重构和算法变化，附验证说明；至少一名相关同事审核。不要提交机器凭据、真实受试者标识、个人路径、缓存、检查点、临时研究产物。增加依赖应说明用途并放入合适的可选依赖组。
